## [1.0] - 2026-08-26

This release was authored by Ryan Morin.

- Ported HMF Tools' LILAC ([hartwigmedical/hmftools](https://github.com/hartwigmedical/hmftools/tree/master/lilac)) to native Snakemake rules -- HLA class I typing (A/B/C, 4-digit resolution), somatic mutation assignment per allele, allelic imbalance, and complete allele loss, from BAM files. The WGS-native alternative to `modules/mhc_hammer/1.0` (LILAC is validated at 30-40x germline / 100x tumour WGS depth; MHC Hammer's own design was validated and tuned for WES).
- Installed via the bioconda package `hmftools-lilac` (confirmed available up to `2.0.1`, matching the latest GitHub release). GPLv3-licensed -- unlike `mhc_hammer`'s upstream, no academic-use redistribution restriction and no user-supplied-clone requirement; installed the same way as any other conda-managed tool this repo wraps.
- No BAM slicing/personalised-reference/realignment/allele-specific-BAM-splitting pipeline needed: LILAC does its own HLA-region fragment filtering directly against a full BAM in one invocation. One rule (`_lilac_run`) per matched tumour/normal pair (`CFG["paired_runs"]`, narrowed to `pair_status == "matched"` -- HLA typing needs the patient's own germline sample, same reasoning as `mhc_hammer`) does typing, and -- when the optional `inputs.gene_copy_number`/`inputs.somatic_vcf` are available for that pair -- tumour copy number and somatic mutation assignment, all at once.
- `options.version_map` (genome_build -> LILAC's own `-ref_genome_version`, `"37"`/`"38"`) and `options.use_masked_ref` mirror `modules/hmftools/1.1`'s own solved pattern for the same genome-build-flavour classification problem, kept as this module's own separate copy (same as `modules/sage/1.1` does) rather than a cross-module reference. `-ref_genome_version`'s exact accepted value format was confirmed against the real installed `hmftools-lilac=2.0.1` jar's own registered config item description (`"37 or 38"`), not just LILAC's own README (whose example commands show `-ref_genome_version V37` -- both forms parse without error, but the bare numeric form matches the tool's own authoritative description).
- `_lilac_download_reference` fetches LILAC's own 3 required resource CSVs directly from `www.bcgsc.ca/downloads/morinlab/hmftools-references/lilac/` -- the same pre-extracted, per-tool reference mirror `modules/hmftools/1.1`/`modules/sage/1.1` already use for this upstream tool suite (~30MB combined, one cohort-wide download, no genome-build wildcard needed since all 3 files are build-independent). Originally pointed at the official HMF/oncoanalyser reference-data bundle directly (~5.6GB per genome-build family, since that bundle contains every hmftools tool's reference data, not just LILAC's) before this lighter mirror was set up.
- `inputs.gene_copy_number`/`inputs.somatic_vcf` are optional, existence-checked per pair (same pattern as `modules/mhc_hammer/1.0`'s `inputs.battenberg_cellularity_ploidy`) -- real example defaults point at `modules/hmftools/1.1`'s PURPLE output and `modules/sage/1.1`'s combined VCF output respectively, matching LILAC's own README guidance ("from SAGE or PURPLE, other callers also accepted").
